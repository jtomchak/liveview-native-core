## Authentication milestone

Demo credentials are configured only in development/tests: `workshop` / `workshop-demo`, `studio` / `studio-demo`. Production has no demo credential configuration. Native cookies are origin-scoped in iOS Keychain and Android Keystore-encrypted preferences. JavaScript submits passwords once and retains no cookie/token. The server stores expiring, revocable sessions in the same durable account object; every task mutation validates authorization atomically. Cookies are signed, HttpOnly and expire after 24 hours; production marks them Secure. Signed session fields are client-readable, not encrypted.

`postForm` uses Rust's CSRF token, validates the origin, and waits for a new connected document. Rust now carries HTTP method/body through reconnect; POST redirects cannot leave the original origin. The current core follows redirects as GET (Phoenix POST-redirect-GET); general 307/308 method-preserving redirects are not supported. Cookie/session payload debug logging was removed. Successful form submission is distinct from confirmed sign-in in telemetry.

Logout clears every client/document/cookie jar at the origin and blocks late persistence writes. **Online logout confirms server revocation. If the request fails, local credentials are still deleted; remote revocation is unconfirmed and the old server session expires after 24 hours.** The sample does not retain credentials for durable offline revocation retries. Telemetry distinguishes `auth.local_logout` from confirmed `auth.logout`. Use one active client per origin: separate Rust jars share durable storage but do not merge concurrent cookie changes.

[Runtime evidence](checklist-auth-verification.json) verifies invalid credentials, restored studio session after process termination/relaunch, account switching and protected document clearing on both platforms. Screenshots: [iOS](screenshots/checklist-auth-ios.png), [Android](screenshots/checklist-auth-android.png). `scripts/checklist-auth-smoke.js` leaves studio signed in; terminate/relaunch the app, then run `scripts/checklist-auth-restore-smoke.js`. Debug-only `__lvnSession` enables these transport checks and never contains cookies.

Unsigned iOS simulator executables cannot access Keychain. Run `bash scripts/build-simulator.sh <simulator-UDID>` for a reproducible ad-hoc simulator build with temporary app-scoped entitlements. Physical devices require normal provisioning/signing; this helper never changes device configuration.

## Navigation milestone

Expo Router 58 owns the installed RN route stack and OS deep links. A root provider owns one Rust client; route screens share it and render only when the committed `data-route` matches the visible route. Server push/replace is mirrored after document commit; session/request identity guards reject stale async navigation. Rust supplies history IDs and back/forward, and its callback rejects foreign origins. Server ownership checks apply to every list/checklist/task route. Authentication resets the visible stack. Arbitrary routes and uninstalled components are unavailable.

Supported URLs: `/checklists`, `/checklists/:id`, `/checklists/:id/tasks/:task_id`, `/checklists/:id/tasks/:task_id/edit`, `/sign-in`; app scheme `lvn-checklist://checklists/...`. Query values are not exposed as a filter UI yet. Header gestures are disabled; header and Android hardware back use core history. At the logical root, Android back exits rather than popping an unrelated Expo entry. A navigation that fails or times out rolls the visible stack back to its last committed route; a native accepted-but-uncommitted history entry may still require reconnect recovery.

The sample uses `useLiveView({ suspendInBackground: false })` to retain the one client/history across OS URL delivery. Background stop/restart at the original endpoint could otherwise overwrite a warm deep link. The library keeps its previous default background teardown for callers who choose it. Retention is subject to OS suspension/network limits; it is not a background execution service. Active native channel errors remain observable and the Reconnect control restores the active route, including the offline editor, as verified in final validation.

[Runtime evidence](checklist-navigation-verification.json) records both platforms' list/detail/task/back/forward, server replace, foreign URL rejection, and warm OS deep links that remain in the same session after five seconds. Screenshots: [iOS](screenshots/checklist-navigation-ios.png), [Android](screenshots/checklist-navigation-android.png). Native APIs acknowledge navigation queueing; committed route metadata confirms the document. `scripts/checklist-navigation-smoke.js` requires the debug app/Metro, and `scripts/checklist-deep-link-smoke.js` verifies an OS-opened workshop task route.

SDK58 Router, Screens, Safe Area, Linking, Constants and Splash Screen are pinned in the example. No Reanimated/Worklets dependency was needed. Both iOS and Android Hermes exports passed. Generated native projects were rebuilt after scheme/autolinking changes; generated sources remain ignored.

## Forms milestone

Installed `Form`, `TextInput`, `Switch`, `HiddenInput`, `FormButton` and Cancel render as native controls. Fields are controlled locally; validation sends the whole URL-encoded form after a 250ms debounce. Dirty values and their original record version survive server diffs and route changes. Account/endpoint changes and logout clear the bounded in-memory draft store. Process-death persistence follows in the SQLite milestone.

Phoenix validates ownership, field limits and the submitted version before a durable save. Telemetry exports fixed form outcome labels and duration only. Form values and business reply objects are not logged. The native form API sends an optional component target as an explicit nullable argument because Expo Modules 2.0 disallows native parameter defaults.

Native testing found two protocol details. A business reply is in `diff.r`; Rust removes this top-level object before decoding rendering fragments, preserving numeric and nested root markers. Phoenix drops business acknowledgements when the same response redirects. Saves return a typed, sequence-correlated acknowledgement first; the renderer clears only the matching draft and then replaces the route with `data-saved-route`. Authorization denials follow the same acknowledgement-first rule. Session-revocation redirects remain supported.

Filename, MIME and size are displayed locally; telemetry exports transfer duration and fixed cancellation labels only. This is a foreground transfer; OS background upload services and durable upload queues are outside this sample.

Transfers run independently of the event loop so navigation and cancellation remain available. `cancelUpload` stops the field's native transfer before sending the installed server cancellation event. The server confirms progress. Transfer completion is distinct from saving an attachment. The small synchronous writes are measured with fixed numeric telemetry; larger production datasets should move work off the JS frame path. No cookies, passwords or authentication tokens enter SQLite. Cached business data is plaintext in the app sandbox.

## Durable command milestone

Offline completion and edited task fields become typed desired-state commands in SQLite. Each command binds a random operation ID, account, task and original expected version. The queue is scoped by endpoint/account, limited to 100 pending commands and one command per task. Generic DOM clicks and uploads are not queued. Replay requires a connected session with confirmed matching account; connection loss and unavailable replies retry the same ID/body. Late receipts from a retired session/account cannot clear current state.

Phoenix serializes authorization, version checking, mutation and receipt storage in one synced account record. Duplicate IDs return the original receipt without a second mutation. Changed bodies under the same ID are rejected. Receipts last seven days, with 1,024 active receipts per account; expired IDs require explicit review/reapply with a fresh ID. IDs more than five minutes in the future are rejected, so device clock accuracy matters. Receipt quota refuses new work while allowing retained duplicates. This remains single-node sample storage.

A conflict keeps the desired values and original draft. The panel compares desired and confirmed state; explicit reapply uses a fresh ID and the latest confirmed version. A successful receipt clears only the matching draft sequence, preserving newer edits. Discard retains the draft and does not undo an already dispatched server mutation. Logout/account/origin changes clear the local queue. Offline cached authentication remains visibly unverified.

[Native evidence](checklist-commands-verification.json) records both installed apps queuing through the mounted offline editor, restoring the same IDs and draft associations after termination, replaying automatically, retaining conflicts and invoking the mounted reapply callback. Screenshots: [iOS](screenshots/checklist-commands-ios.png), [Android](screenshots/checklist-commands-android.png). The command proof scripts mutate sample records and must run sequentially per platform. Native JSON now preserves integers for strict expected-version validation. Domain-call failures return a safe retryable unavailable status; GenServer diagnostic state and reasons are redacted. Telemetry exports fixed outcomes and numeric durations/counts only.

## Incremental bridge milestone

First documents and replacements deliver full snapshots. Within a generation, both native modules coalesce callbacks for 8 ms, compare normalized nodes with their last delivered baseline and send bounded upserts/removals; unchanged documents are skipped and larger patches fall back to full snapshots. Status events carry no document. Event revision and document revision are independent. A generation change cancels pending old work. Swift ordinary statuses and snapshots share the serial delivery queue, preventing status from overtaking a replacement snapshot.

JS applies patches to a private map, validates the complete tree atomically, and publishes only coherent documents. Bounds are 4 MiB retained document, 20,000 nodes and depth 256. A missing base, malformed patch or replacement without a full snapshot retains the last good tree, blocks actions and requests one full resync. Native `requestSnapshot` cancels pending patch work and emits a fresh full revision. Equal nodes retain identity; changed subtree versions propagate to ancestors so unchanged siblings can skip React rendering.

[Before/after evidence](checklist-patches-verification.json): iOS 26,748 bytes / four deliveries → 2,039 bytes / one patch (92.38% fewer); Android 26,716 → 2,052 bytes / one patch (92.32% fewer). Both consumed four callbacks in one batch, skipped 38 unchanged rendered nodes, updated nine affected nodes, accepted forced full resync and started navigation replacements with a full document. These are single-action Debug simulator/emulator measurements; they are not physical-device release latency/frame benchmarks. Rust still serializes a full normalized snapshot internally, and JS final tree validation still walks the tree. The measured optimization concerns bridge bytes, callback amplification and sibling rendering.

Run `python3 scripts/test-native-patches.py` on macOS/Xcode to execute checks extracted from the production Swift encoder and NativeSession with controlled platform stubs. It verifies ordering, generation cancellation, forced resync and secure-error delivery before close. Both real native app builds and `scripts/checklist-bridge-{measure,verify}.js` verify the installed path. [Node microbenchmarks](parse-patch-baseline.json) compare complete parsing and one-node patch application; they do not measure native rendering. Screenshots: [iOS](screenshots/checklist-patches-ios.png), [Android](screenshots/checklist-patches-android.png).
